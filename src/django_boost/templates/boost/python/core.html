# Python Best Practices - This project uses Python {{ assist.python_version() }}. Use features available in this version. - Use f-strings for string formatting (available in Python 3.6+). - Use `pathlib.Path` for filesystem operations, not `os.path` (unless legacy code requires it). - Prefer `dataclasses` or `NamedTuple` for simple data containers. ## Type Hints - Use type hints consistently: function arguments, return types, and complex variables. - For Django models, use `django-stubs` compatible type annotations when available. - Use `Optional[X]` instead of `X | None` if the project uses Python < 3.10. - Use `from __future__ import annotations` if PEP 604 syntax (`X | Y`) is used with older Python versions. ## Imports - Follow PEP 8 import order: standard library, third-party, local application. - Use `isort` or `ruff` to keep imports organized. - Avoid wildcard imports (`from module import *`). ## Error Handling - Be specific with exception handling: catch `ValueError`, not `Exception`. - Use `contextlib.suppress()` for intentionally ignored exceptions. - Log errors appropriately using `logging.getLogger(__name__)`. ## Performance - Use `select_related()` and `prefetch_related()` to avoid N+1 queries. - Use `iterator()` for large querysets. - Use `bulk_create()` and `bulk_update()` for batch operations. - Avoid loading entire querysets into memory with `list()` unless necessary. - Use `.values()` or `.values_list()` when you only need specific fields. ## Async Support - Django 4.1+ supports async views. Use `sync_to_async()` for ORM calls in async context. - Django 5.0+ has improved async ORM support. Check the project's Django version.
