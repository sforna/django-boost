# Docker Development Environment This project uses Docker Compose for local development (like Laravel Sail). ## Running Commands - Start containers: `docker compose up -d` - Stop containers: `docker compose down` - Rebuild: `docker compose build` - Shell access: `docker compose exec web bash` ## Django Commands in Docker Prefix standard Django management commands with your container runner. For example: - `docker compose exec web python manage.py migrate` - `docker compose exec web python manage.py test` ## Services Common Docker services in Django projects: - **web**: Django application server (gunicorn/runserver) - **db**: PostgreSQL or MySQL - **redis**: Redis for caching/queues - **celery_worker**: Celery worker - **celery_beat**: Celery scheduler - **node**: Frontend build tools (webpack/vite) ## Database - The database host within Docker is the service name (e.g., `db` not `localhost`). - Database credentials should match what's in `docker-compose.yml` and `.env`. ## Environment - Environment variables are in `.env` files, loaded by Docker Compose. - Never commit `.env` files — use `.env.example` for templates.
